# IPAD EDITION: current architecture evidence map

**Research date:** 2026-10-20 (America/Phoenix)
**Baseline:** `8894640543833eaf37bd62b971a0955c26bafa49`
**Method:** Static source inspection across frontend, player-isolation, and persistence audits. All source links and line references are pinned to this baseline. No app behavior was manually exercised, no automated test code was generated, and this report makes no performance or device-validation claims. Future design proposals belong in the feature dossier.

## Existing application boundary

Tripling Season currently presents one active board. One instance each of TokenProvider, DeckProvider, SettingsProvider, TrackerProvider, ToggleProvider, and RulesProvider sits above one MaterialApp; provider initialization also initializes board-order recovery. Provider constructors do not accept a player or game-session scope. [Initialization](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/main.dart#L91-L116); [root composition](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/main.dart#L599-L637).

TokenProvider opens the fixed `items` box and returns all its values. TrackerProvider and ToggleProvider similarly open `trackerWidgets` and `toggleWidgets`; their getters enumerate those whole boxes. Item, TrackerWidget and ToggleWidget contain no player/session ownership field. Utility `widgetId` is an instance identity, not participant identity. Consequently, additional instances of these existing providers still address the same stored board. [Tokens](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/providers/token_provider.dart#L45-L67); [trackers](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/providers/tracker_provider.dart#L41-L46); [toggles](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/providers/toggle_provider.dart#L29-L53); [Item fields](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/models/item.dart#L8-L141).

## Frontend composition and constraints

Startup requests portraitUp and portraitDown globally. The iOS project sets `TARGETED_DEVICE_FAMILY = 1` in its build configurations, while Info.plist separately lists iPad orientations. The Android manifest uses `adjustPan`; the UCrop activity explicitly requests portrait. These are source configuration facts, not a device-support assessment. [Orientation](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/main.dart#L27-L40); [iOS target configuration](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/ios/Runner.xcodeproj/project.pbxproj#L451-L465); [iPad orientation declarations](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/ios/Runner/Info.plist#L68-L74); [Android activity configuration](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/android/app/src/main/AndroidManifest.xml#L24-L45).

ContentScreen merges tokens, trackers and toggles into one sorted `_BoardItem` sequence, listens directly to all three Hive boxes, and renders one ReorderableListView. It owns one expanded-item key and one active-editor flag. Tapping another item collapses the first and returns; collapse unfocuses the app's primary focus. ExpandableCardController allows an asynchronous save failure to veto collapse. [Expansion state](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/screens/content_screen.dart#L49-L108); [mixed board/list](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/screens/content_screen.dart#L252-L380); [collapse contract](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/controllers/expandable_card_controller.dart#L1-L13).

Reordering is disabled during expansion and writes through BoardOrderPersistence. A write blocks the scaffold; a failure opens a non-dismissible recovery dialog. Swipe deletion differs by card: expanded tokens remain dismissible when no inline editor is active; expanded utilities are not. Restored object identity contributes to child keys so stale editors are replaced. [Order-write blocking](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/screens/content_screen.dart#L133-L145); [dismissal and identity](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/screens/content_screen.dart#L384-L485); [reorder handling](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/screens/content_screen.dart#L734-L763).

TokenCard's action area always returns one Row. Ordinary non-emblem tokens have seven buttons, Scute has eight, nominal internal width is 39 logical pixels, and spacing bottoms out at four. The nominal button-area requirements are therefore 297 and 340 logical pixels before outer card padding. This is a calculation from constants, not a rendered minimum-width measurement. Tracker action controls likewise remain in a Row. [Token action layout](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/widgets/token_card.dart#L1133-L1169); [button constants](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/utils/constants.dart#L71-L76); [tracker action layout](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/widgets/tracker_widget_card.dart#L705-L794).

Menus and editors assume the current route stack. Search accepts `selectorMode` without player context; creation closes quantity and search routes with two pops. Artwork selection contains an explicit root-navigator pop. Fixed Hero tags identify the menu/rules controls. MultiplierView also stores one static active State for tooltips, overwritten when another instance mounts. [Search constructor](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/screens/token_search_screen.dart#L22-L28); [creation dismissal](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/screens/token_search_screen.dart#L1070-L1071); [root dismissal](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/widgets/artwork_selection_sheet.dart#L950-L958); [menu](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/widgets/floating_action_menu.dart#L25-L49); [static feedback](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/widgets/multiplier_view.dart#L9-L32).

## Rules, creation, and event paths

RulesProvider owns nine preset counts in unqualified SharedPreferences keys and all custom rules in one `tokenRules` box. Its evaluation API accepts token characteristics and quantity, without session/player arguments. Outcomes include multiplication, replacement and companion creation. Companion evaluation continues from the next rule; display aggregation deliberately does not replace per-event creation results. Counter modifiers use the same provider's preset state. [Rules storage](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/providers/rules_provider.dart#L150-L229); [evaluation](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/providers/rules_provider.dart#L560-L706); [counter calculation](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/providers/rules_provider.dart#L749-L767).

TokenCreationService is an existing shared commit boundary. Requests include a resolved result, artwork, order, sickness/tapped settings, merge policy and event policy. Compatible merge searches every `tokenProvider.items` entry. Compatibility means exact identity and artwork with no built-in/custom counters; it does not include ownership. Commits proceed sequentially and report partial outcomes on failure, without transaction-level rollback. [Request/commit implementation](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/services/token_creation_service.dart#L16-L164); [merge predicate](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/services/token_merge_compatibility.dart#L7-L48).

New service-created stacks insert with automatic entry events disabled, then apply sickness and emit the selected event. Companion creation skips the primary result; peer creation commits every result. Artwork caching is asynchronous and checks that the item remains boxed with the same artwork URL. [Creation/events/cache](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/services/token_creation_service.dart#L116-L184); [companion and peer entry points](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/services/token_creation_service.dart#L218-L258).

## Deck setup versus live game state

Deck save collects the whole mixed board, sorts it, and deduplicates tokens by identity plus artwork URL. TokenTemplate contains characteristics/art/order, not active quantity/status/counters. Load creates token stacks at quantity zero, trackers at their defaults and toggles OFF; utilities receive fresh UUIDs. Accordingly, the existing deck path saves a setup, not a live-game snapshot. [Save](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/screens/decks_list_screen.dart#L781-L826); [token template](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/models/token_template.dart#L8-L83); [load](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/providers/deck_provider.dart#L600-L620); [tracker reconstruction](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/models/tracker_widget_template.dart#L94-L114); [toggle reconstruction](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/models/toggle_widget_template.dart#L74-L89).

Clear/load deletes all tokens and utilities. Append/load finds the maximum mixed-board order, then restores interleaved templates. JSON export uses schemaVersion 3, app version/date, and token/utility templates; import rejects absent versions and versions above three. Export stores artwork URLs/options rather than embedded image bytes. Deck customArtworkUrl exists in Hive but is absent from this export map. [Load modes](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/providers/deck_provider.dart#L535-L620); [export/import](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/providers/deck_provider.dart#L304-L381); [deck fields](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/models/deck.dart#L9-L36).

## Persistence, undo, ordering, and recovery

Item setters persist quantity, status, colors, type and counter edits directly through HiveObject.save; tracker and toggle methods also save directly. Item fields run through 17, including independent power/toughness counters. Snapshot restoration replaces instances while preserving keys; providers already re-resolve captured keys after detachment. [Fields/setters](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/models/item.dart#L8-L141); [delayed resolution](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/providers/token_provider.dart#L31-L39).

BoardUndoSnapshot clones all tokens, trackers and toggles. Restore clears all three boxes and writes cloned records directly, without game events. RulesStateSnapshot separately contains preset counts and custom-rule enabled flags by key; restore does not recreate deleted rules. ContentScreen's wipe flow snapshots, rolls back failures and offers a mandatory Undo/Accept dialog. These snapshots are in memory and have no participant scope. [Board undo](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/services/board_undo_snapshot.dart#L10-L44); [rules undo](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/providers/rules_provider.dart#L871-L907); [wipe workflow](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/screens/content_screen.dart#L1039-L1142).

BoardOrderPersistence serializes work through a static Future tail and stores one `pendingV1` plan in `boardOrderOperations`. It snapshots all three boxes, validates journal rows before writing, skips deleted models, flushes each box and removes the journal. Initialization replays recovery and normalizes ambiguous positions; moves reconstruct the current mixed sequence. Its `kind` discriminator identifies model type, not player or list ownership. [Complete order implementation](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/services/board_order_persistence.dart#L13-L162).

Native Hive boot attempts normal open, backup restore, then deletion/reopening of a corrupt box. Top-level failures are swallowed, so return does not establish that every box opened; provider initialization can subsequently enter the error screen. Web uses sequential opens without filesystem backups. Native boot asynchronously overwrites one backup generation by copying seven Hive files sequentially. SharedPreferences, uploaded artwork and the order journal are outside that explicit backup list. Successful restoration is not recorded in `wipedBoxes`. [Startup](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/database/hive_setup.dart#L41-L101); [recovery](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/database/hive_setup.dart#L125-L163); [backup](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/database/hive_setup.dart#L203-L236); [provider failure](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/main.dart#L118-L145).

The lifecycle handler checks provider readiness on resume; it contains no coherent-session flush on pause/detach. Weekly compaction acts on `items` and stores an app-wide timestamp. [Lifecycle](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/main.dart#L509-L526); [compaction](https://github.com/didymusbenson/Doubling-Season/blob/8894640543833eaf37bd62b971a0955c26bafa49/lib/database/database_maintenance.dart#L16-L76).
